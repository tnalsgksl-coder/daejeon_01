# 비마이마케터(BMYM) 블로그 스타일 가이드

> **분석 대상**: bemymarketer.net 블로그 3편 (`/blog/100`, `/blog/102`, `/blog/33`)
> **분석 범위**: 주제는 빼고 말투·문체·구성·강조·이미지 패턴만 정리했습니다.
> **용도**: 이 파일 하나만 보고 같은 톤의 글을 쓰기 위한 작성 지침입니다.
> **예문 안내**: 아래 예문은 원문을 옮긴 것이 아니라 **같은 문체로 새로 쓴 예시**입니다. 주제도 일부러 원문과 다르게 잡았습니다(재구매, 리뷰, 상세페이지 등).
> **표기 약속**: 이 문서에서 `==텍스트==`는 **형광펜**(노란 배경 하이라이트, HTML `<mark>`)을 뜻합니다. `**텍스트**`는 볼드입니다.

## 0. 한눈에 보기: 핵심 규칙 12가지

1. 평서문은 전부 **합니다체**로 씁니다. 해요체는 질문(`~ㄹ까요?` `~나요?`)과 권유(`~해 보세요`)에만 씁니다.
2. **느낌표, 이모지, 유행어는 0개**입니다. 차분하고 단정한 실무 컨설턴트 톤을 유지합니다.
3. **한 줄에 한 문장(또는 한 절)**씩 씁니다. 한 줄은 평균 25자 안팎, 문단은 3~6줄입니다.
4. 독자는 **"대표님들"**(브랜드·쇼핑몰 운영자)이고, 화자는 **"저희"**(팀)입니다. 가끔 **"저는 / 제가"**도 씁니다.
5. 핵심은 **"A가 아니라 B"**, **"A이지, B는 아닙니다"** 같은 대조 구문으로 정의합니다.
6. **도입부는 고정 4단계**입니다: 흔한 장면 → 흔한 반응 → 볼드 셀프 체크 3개 → 형광펜 명제 + "오늘은 ~해 보겠습니다."
7. **마무리는 고정 3단계**입니다: 구분선 → 형광펜 2줄 요약 → "대표님들, 오늘은 ~해 보세요." + 볼드 마지막 문장.
8. **형광펜은 글당 6개 안팎**만 씁니다(도입 1, 섹션 결론 4, 마무리 1).
9. **볼드는 글당 25개 안팎**입니다. 문단 속 핵심 구나 문단 마지막 결론 줄에 씁니다.
10. **이미지는 글당 3장**이고 전부 **요약 표 형태의 인포그래픽**입니다. 섹션 끝(형광펜 바로 다음)에 두고, 캡션은 한 문장입니다.
11. 숫자 예시는 반드시 **"가상 예시"라고 밝힙니다.** 공식 기준, 현장 어림값, 팀의 비유도 서로 구분해서 말합니다.
12. 글은 언제나 **"오늘 바로 할 수 있는 행동 하나"**로 닫습니다.

## 1. 화자와 독자

| 항목 | 설정 |
|---|---|
| 화자 | 실무를 오래 해 본 마케팅 대행사의 팀 또는 대표. 기본은 **"저희"**. 개인 지론을 말할 때만 "저는 ~할 때 이 비유를 자주 씁니다", "제가 늘 강조하는 부분이기도 합니다"처럼 1인칭 단수 |
| 작성자 표기 | 팀 명의(예: "OO팀") 또는 대표 명의. 명의가 달라도 톤은 완전히 같음 |
| 독자 | 자사몰·스마트스토어를 운영하는 브랜드 대표, 광고 운영자 |
| 호칭 | **"대표님들"** (글당 1~2회, 주로 마무리와 "알 필요는 없습니다" 같은 안심 문장). 그 밖에는 "운영자", "고객" 같은 3인칭 |
| 독자 사업 지칭 | **"우리 계정", "우리 상품", "우리 사업", "우리 쪽 기록"** — 독자 입장에서 '우리'를 씀 |
| 관계 | 위에서 가르치는 강사가 아니라, 옆에서 같이 숫자를 보는 실무 파트너. 겁주지 않고, 과장하지 않고, **확인할 순서**를 알려 줌 |
| 쓰지 않는 호칭 | "여러분", "고객님", "독자 여러분" |

**태도 키워드**: 차분함 · 실무적 · 근거 구분 · 겸손하지만 분명한 단정 · "순서"와 "기준" 중시 · 성급한 결론 경계

## 2. 말투와 문장 끝맺음

### 2-1. 어미 분포

| 쓰임 | 어미 | 비중 |
|---|---|---|
| 평서 (기본) | `~입니다` `~습니다` `~합니다` | 전체 문장의 대부분 |
| 진행 예고 | `~해 보겠습니다` | 글당 3~7회 |
| 질문 | `~ㄹ까요?` `~나요?` `~인가요?` `~아닌가요?` | 소제목, FAQ, 독자 속마음, 수사 의문 |
| 권유·지시 | `~해 보세요` `~하세요` `~두세요` `~보시면 됩니다` | 본문 실무 팁, FAQ 끝, 마무리 |
| 가벼운 구어 | `~거죠.` `~라고요.` `~해 보죠.` | 글당 0~2회. 딱딱함을 살짝 풀 때만 |
| 존대 표현 | `~하십니다` `말씀드린 대로` `말씀드리겠습니다` | 독자 행동을 말할 때 ("많이들 오해하십니다") |

### 2-2. 즐겨 쓰는 종결 표현

| 표현 | 쓰임 | 예 (새로 쓴 예문) |
|---|---|---|
| `~는 겁니다` | 해석·진단을 내려 줄 때 | 재구매가 첫 주문에서 끝나는 구조인 겁니다. |
| `~셈입니다` | 다른 말로 환산할 때 | 결국 할인으로 첫 구매를 사 온 셈입니다. |
| `~편입니다` | 저희 방식, 경향 | 저희는 상세페이지 수정을 한 번에 묶어서 하는 편입니다. |
| `~에 가깝습니다` | 단정은 피하되 방향은 분명하게 | 리뷰 수보다 리뷰 내용의 문제에 가깝습니다. |
| `~일 뿐입니다` | 과대해석을 막을 때 | 같은 주에 함께 움직였다는 기록일 뿐입니다. |
| `~수 있습니다` / `~수도 있습니다` | 가능성 (글당 2~12회) | 쿠폰 때문에 들어온 손님일 수도 있습니다. |
| `~가능성이 큽니다/높습니다` | 확률적 판단 | 이미 다른 제품과 비교 중인 고객일 가능성이 높습니다. |
| `~근거는 없습니다` / `~보증은 아닙니다` | 통념 바로잡기 | 모든 상품에 통하는 숫자라는 근거는 없습니다. |
| `~할 차례입니다` | 마지막 행동 지시 | 그렇다면 첫 화면부터 다시 볼 차례입니다. |

### 2-3. 체크리스트·표·이미지 안의 문장
- 도입부 셀프 체크 3개는 **한다체 평서**로 끝냅니다: `~부터 바꾼다`, `~라고 생각한다`, `~로 본다`
- 표 셀과 이미지 속 글은 **명사형**으로 짧게 끊습니다: `검색해서 비교 중`, `첫 화면 수정`, `+24만 원`
- 메모 박스 속 양식은 `라벨: 내용` 형태입니다: `가설: ~`, `확인할 숫자: ~`, `바꾸지 않을 것: ~`

### 2-4. 쓰지 않는 것
- 느낌표(!), 이모지, `ㅎㅎ` `ㅠㅠ`, `~랍니다`, `~했어요!`
- `꿀팁`, `대박`, `무조건`, `100%`, `필수!`, `치트키` 같은 과장·유행어
- 반말, 명령조(`~해라`), 감탄문
- **해요체 평서문**(`~해요.` `~거든요.`) — 평서문은 합니다체로만
- `~것 같습니다`의 남발. 추측은 `~수 있습니다` / `~가능성이 큽니다` / `~에 가깝습니다`로 씁니다.

## 3. 문장 호흡과 줄바꿈 ⭐ 가장 눈에 띄는 특징

### 3-1. 측정값 (세 글 평균)

| 항목 | 값 |
|---|---|
| 한 줄 길이 | 중앙값 24~27자(공백 포함). 대부분 16~37자 |
| 문단당 줄 수 | 평균 4.3줄 (1~7줄) |
| 줄 끝 | 약 60%는 마침표, 약 12%는 쉼표, 나머지는 절 중간에서 끊음 |
| 글 전체 문단 수 | 46~51개 |
| 본문 분량 | 공백 포함 약 6,300~6,500자 (공백 제외 약 4,900자). 사이트 표기 "8분 읽기" |
| 느낌표 | 0개 |

### 3-2. 규칙
1. **한 줄 = 한 호흡.** 문장이 끝나면 문단 안에서 줄을 바꿉니다(`<br>`, 마크다운에서는 줄 끝 공백 2칸).
2. 긴 문장은 **절 단위로** 끊습니다. `~하면` `~인데` `~하고,` `~지만` `~이라면` 뒤에서 줄을 바꿉니다.
3. 3~6줄을 한 문단으로 묶고, 문단 사이는 빈 줄로 띄웁니다.
4. 문단의 **마지막 1~2줄을 볼드 결론**으로 두는 경우가 많습니다.
5. 리듬은 **짧은 단문 연타 → 조금 긴 설명 → 짧은 결론**입니다.
6. 쉼표로 병렬 리듬을 만듭니다: "줄일지, 바꿀지, 새로 만들지." / "고칠 건 고치고, 기다릴 건 기다리고, ~"

### 3-3. 줄바꿈 예시 (새로 쓴 예문)

❌ 피해야 할 형태

```text
리뷰가 많은데도 구매 전환이 낮다면 리뷰 개수보다 리뷰가 어떤 이야기를 하고 있는지 먼저 봐야 합니다. 대부분 배송이 빠르다는 말뿐이라면 고객이 망설이는 지점에는 답을 못 주고 있는 겁니다.
```

✅ 이 블로그의 형태 (줄마다 `<br>`)

```markdown
리뷰가 많은데도 구매 전환이 낮다면
리뷰 개수보다 리뷰 내용을 먼저 봐야 합니다.
대부분 “배송 빨라요”뿐이라면
고객이 망설이는 지점에는 아무 답도 못 주고 있는 겁니다.
**리뷰는 숫자가 아니라, 망설임에 대한 답입니다.**
```

## 4. 자주 쓰는 표현과 어휘

### 4-1. 시그니처 문형 (반드시 섞어 쓸 것)

**① 대조 정의: "A가 아니라 B"** — 가장 많이 쓰는 문형 (글당 3~17회)
- 템플릿: `[대상]은 [흔한 오해]가 아니라 [진짜 역할]입니다.`
- 예: 상세페이지는 제품 소개서가 아니라 망설임을 하나씩 지우는 순서입니다.
- 소제목, 형광펜, 캡션, FAQ 답변 어디에나 씁니다.

**② 한정 정의: "A이지, B는 아닙니다"**
- 템플릿: `[대상]은 [실제 역할]이지, [과한 기대]는 아닙니다.`
- 예: 리뷰 이벤트는 첫 리뷰를 모으는 도구이지, 재구매를 만들어 주는 도구는 아닙니다.

**③ 저희 방식 선언: "그래서 저희는 ~합니다 / ~하는 편입니다"**
- 근거를 설명한 다음 팀의 실무 원칙을 붙이는 문형입니다. 글당 2~5회.
- 예: 그래서 저희는 쿠폰율보다 쿠폰을 쓴 뒤 30일 재방문을 먼저 봅니다.

**④ 진행 예고: "~해 보겠습니다"**
- `차근차근 풀어 보겠습니다` `하나씩 채워 보겠습니다` `숫자로 한 번 보겠습니다` `따라가 보겠습니다` `다시 써 보겠습니다` `그려 보겠습니다`

**⑤ 가정 도입: "~라고 해 보겠습니다 / ~라고 해 보죠 / ~라고 가정합니다"**
- 예: 한 달 광고비가 300만 원이라고 해 보겠습니다.

**⑥ 오해 지점 짚기**
- `여기서 많이들 오해하십니다.` `여기서 오해하기 쉬운 부분이 있습니다.` `아마 가장 많이 받는 질문일 겁니다.`

**⑦ 우선순위 제시: "~부터 봅니다 / 확인합니다 / 의심합니다"**
- `먼저` `그 전에` `그다음` `그때 비로소` `첫째·둘째·셋째`와 짝을 이룹니다.
- 예: 측정과 결제가 정상이라면, 그때 비로소 소재를 의심합니다.

**⑧ 독자 속마음 대사로 받아치기**
- 독자가 할 법한 반문을 큰따옴표로 던지고, 바로 다음 문단에서 받습니다.
- 예: “그럼 리뷰만 많이 쌓이면 되는 거 아닌가요?” → 여기서 많이들 오해하십니다.

**⑨ 비유·예시로 연결**
- `~로 생각해 보면 쉽습니다.` `[업무]로 옮기면 이런 장면입니다.` `~로 보면 이해가 쉽습니다.` `예를 들어 볼까요.` `아주 단순하게 그려 보겠습니다.`

**⑩ 수사 의문으로 장면 열기**
- `~를 먼저 보여 주면 어떨까요?` `클릭한 사람은 며칠 동안 무엇을 찾아보고 있을까요?`

### 4-2. 문장 맨 앞 접속어
빈도순: **그래서** > **그런데** > **다만** > **반대로** > 그리고 / 또 하나, / 여기서 / 그러니 / 물론
- **그래서**: 한 글에 7~11번 나올 만큼 많이 씁니다. 논리 전개의 축입니다.
- **그런데**: 도입부 반전, 통념 뒤집기
- **다만**: 앞에서 한 주장을 스스로 제한할 때
- **반대로**: 다른 경우를 대칭으로 보여 줄 때
- **또 하나,**: 같은 맥락의 두 번째 사례를 붙일 때

### 4-3. 즐겨 쓰는 어휘

| 계열 | 어휘 |
|---|---|
| 판단 | 기준, 단서, 신호, 근거, 순서, 흐름, 원인, 가설, 확인, 구분, 단정 |
| 실무 동작 | 손대다, 손을 쓰다, 손이 가다, 건드리다, 흔들리다/흔들림, 묶어서, 나란히, 따로 떼어, 한 줄로 남기다, 미리 정해 두다 |
| 단위 | 칸, 줄, 장, 단계, 구간 |
| 장면 | 장면, 순간, 회의, 화면, 현장 |
| 정도 부사 | 차근차근, 막연히, 한꺼번에, 한 번에, 딱 한 가지, 생각보다, 비교적 |
| 감각 비유 | "손이 덜 떨립니다", "손이 먼저 갑니다", "한 번에 뛰어가지 마세요" |

### 4-4. 용어 처리
- 어려운 영어 개념은 **한국어로 먼저 풀고**, 영어는 괄호나 "흔히 ~라고 부르는"으로 붙입니다.
  - `국소 최적점(local optimum)` / `혼합 비율, 흔히 블렌디드 ROAS라고 부르는 숫자`
- 툴 이름 대신 **기능으로 부르기도** 합니다. 예: UTM → "유입 경로 표식", GA → "쇼핑몰 접속 통계"
- 업계 약어(CPA, CPM, ROAS, CTA 등)는 그대로 쓰되, 첫 등장 때 맥락을 붙입니다.
- 처음 나오는 개념어나 화면 상태명은 **작은따옴표**로 감쌉니다: ‘리뷰 설계’, ‘학습 중’

## 5. 글 전체 구조 (템플릿)

```markdown
[카테고리 라벨]  (예: 퍼포먼스 / 콘텐츠)
# [개념]이란? [실무 질문·이유·방법]
```

### 5-1. 글 제목 패턴
- 기본형: **`[개념]이란? [부제]`**
- 부제 유형: `~하는 이유`, `~하는 법`, `~전에 알아야 할 것`, `~보다 먼저 볼 것`
- 현장에서 듣는 말을 큰따옴표로 넣기도 합니다: `[개념]이란? “[현장의 말]” 전에 알아야 할 것`
- 개념이 여러 개면 가운뎃점으로 묶습니다: `A·B·C란? ~`
- 새로 쓴 예:
  - 재구매율이란? 첫 구매 쿠폰보다 먼저 설계해야 하는 이유
  - 리뷰 설계란? 별점보다 망설임에 답하는 리뷰를 모으는 법
  - 상세페이지 첫 화면이란? “전환율이 낮다”는 말 전에 열어 볼 것

### 5-2. H2 소제목 유형 (섞어서 사용)

| 유형 | 템플릿 | 새로 쓴 예 |
|---|---|---|
| 정의형 (첫 H2 고정) | `[개념]이란? [정의 문장]` | 재구매율이란? 두 번째 주문까지 이어진 고객의 비율입니다 |
| 질문+답 | `왜 ~할까요? ~때문입니다` | 왜 쿠폰부터 바꾸면 안 될까요? 원인이 섞이기 때문입니다 |
| 질문형 | `A와 B, 무엇이 다를까요?` | 첫 구매와 재구매, 무엇이 다를까요? |
| 단정형 | `[대상]은 [역할]입니다` | 리뷰는 설득용 숫자가 아니라 답변입니다 |
| 콜론형 | `[행동]: [구체 상황]` | 숫자로 한 번 보겠습니다: 재구매가 절반으로 줄었을 때 |
| 비유형 | `저희 팀이 쓰는 비유: [비유 이름]` | 저희 팀이 쓰는 비유: 첫 구매는 첫 데이트입니다 |
| 수정 전·후형 | `수정 전 [대상]: [문제 한 줄]` | 수정 전 상세페이지: 장점은 많은데 답이 없습니다 |
| 명사구 | `~하는 일` / `~점검표` | 매달 한 장에 적는 재구매 점검표 |

※ 질문형 소제목은 물음표를 생략하기도 합니다 (`~움직이지 않을까요`).

### 5-3. H3 소제목 유형
- **`[항목]: [한 줄 설명 또는 질문]`** — 구조를 쪼갤 때. 예: `첫 화면: 무엇을 파는지 3초 안에 보이는가`
- **순서형** — `그 전에, ~인가요?` / `먼저, ~했나요?` / `둘째, ~인가요?` / `셋째, ~했나요?`
- **FAQ** — `Q. ~인가요?`

### 5-4. 섹션을 잇는 첫 문장
섹션 첫 문장이 앞 섹션을 받아서 이어 주는 경우가 많습니다.
- `앞의 비유를 단계별로 한 번 더 나눠 보면 이렇습니다.`
- `앞에서 말씀드린 대로 모두 가상의 숫자입니다.`
- `같은 가상 제품으로 다시 써 보겠습니다.`

## 6. 도입부 패턴 ⭐ (세 글 모두 같은 4단계)

| 단계 | 내용 | 형식 |
|---|---|---|
| ① 장면 | 독자가 자주 겪는 상황을 2~4줄 짧은 평서문으로 그림. 마지막 줄은 **"그런데~" 반전**이나 **볼드 질문** | 1문단 |
| ② 흔한 반응 | 이럴 때 사람들이 내리는 결론이나 선택지를 나열하거나, 큰따옴표 대사 2개로 보여 줌. `~때문입니다.` 또는 `~보세요.`로 마무리 | 1문단 |
| ③ 셀프 체크 | **`1.` `2.` `3.` 번호 + 전체 볼드**, 한다체. 독자가 흔히 하는 잘못된 행동·통념 3개 | 1문단 (3줄) |
| ④ 명제+예고 | `하나라도 해당된다면 ~` 같은 진단 → **형광펜 명제("A가 아니라 B")** → `오늘은 ~부터 ~해 보겠습니다.` 또는 `저희는 이 작업을 ‘~’라고 부릅니다.` | 1문단 |

- 도입부에는 소제목, 이미지, 인사말이 없습니다.
- 도입부 전체는 4문단, 약 15줄입니다.

### 도입부 예시 (새로 쓴 예문, 주제: 재구매)

```markdown
첫 구매 쿠폰을 넉넉하게 걸었습니다.
신규 주문은 확실히 늘었습니다.
그런데 한 달이 지나도 두 번째 주문이 거의 없습니다.
**쿠폰이 약했던 걸까요, 아니면 제품이 문제일까요?**

이럴 때 회의는 보통 둘 중 하나로 정리됩니다.
“쿠폰을 더 키우자.”
“신규 유입을 더 늘리자.”

**1. 재구매가 없으면 쿠폰 할인율부터 올린다**
**2. 리뷰가 많으면 재구매도 자연히 따라온다고 생각한다**
**3. 첫 구매 고객과 두 번째 구매 고객을 같은 숫자로 본다**

하나라도 해당된다면, 아직 재구매를 할인 문제로만 보고 있는 겁니다.
==재구매는 할인의 결과가 아니라,
첫 구매 경험이 약속을 지켰는지에 대한 답입니다.==
오늘은 이 숫자를 어디서부터 봐야 하는지 차근차근 풀어 보겠습니다.
```

## 7. 본문 섹션 내부 패턴

H2 섹션 하나는 보통 4~7문단이고, 다음 흐름을 따릅니다.

1. **주장·정의**: 섹션의 결론을 첫 문단에서 먼저 말합니다.
2. **쉬운 예시나 장면**: `~로 생각해 보면 쉽습니다.` 가상의 인물(A씨·B씨·C씨)이나 가상의 제품을 씁니다.
3. **실무 적용**: `[업무]로 옮기면 이런 장면입니다.` `예를 들어 볼까요.`
4. **스스로 제한**: `다만 ~이지, ~라는 뜻은 아닙니다.` `물론 ~.`
5. **저희 방식**: `그래서 저희는 ~합니다.`
6. **형광펜 결론**: 섹션 핵심을 한 문장으로 (대조 구문)
7. (해당 섹션이면) **이미지 + 캡션**

### 7-1. 가상 인물·가상 제품 장치
- 개념 여러 개를 한 이야기로 묶을 때 **A씨, B씨, C씨** 같은 가상 인물을 세웁니다. 이름은 볼드로 씁니다(`**A씨**는 ~`).
- 예시 제품도 `가상의 ~`라고 밝히고, 사양(용량, 시간, 가격)까지 구체적으로 가정합니다.
- 고지 문장은 필수입니다:
  - `설명을 위해 만든 장면입니다.`
  - `이 글의 제품과 숫자는 모두 설명을 위한 가정이며 실제 성과가 아닙니다.`
  - `특정 사례를 옮긴 것이 아니라 비교를 위해 새로 쓴 예시입니다.`

### 7-2. 비유 쓰는 법
- 섹션 하나를 통째로 비유에 씁니다(`저희 팀이 쓰는 비유: ~`).
- 순서: **비유 소개 → 개념에 대입 → 비유의 한계를 스스로 밝힘 → 비유를 '질문 도구'로 정리**
- 비유는 일상적인 것(사진, 산, 시소, 옷 가게처럼 누구나 그려지는 장면)을 고릅니다.
- 한계 고지 템플릿:
  - `다만 이건 이해를 돕는 비유이지, 실제 구조가 그렇다는 뜻은 아닙니다.`
  - `이건 [법칙·공식]이 아니라 [용도]를 정할 때 쓰는 작업 비유입니다.`
- 정리 템플릿: `비유는 결론이 아니라, [무엇]을 떠올리게 하는 도구입니다.` 같은 형광펜 한 줄

### 7-3. 숫자 예시 쓰는 법
- 단위까지 구체적으로 씁니다: `광고비 60만 원`, `1,500만 원`, `약 77%`, `2%에서 1%로`
- 숫자와 단위 띄어쓰기: `60만 원`, `40초`, `150ml`. 천 단위 쉼표를 씁니다.
- 계산식을 본문에 그대로 보여 줍니다: `1,500 ÷ 300 = 5.0배`, `1,710만 원 × 40% − 360만 원 = 324만 원`
- 숫자 예시는 **'가정' 라벨 메모 박스** 안에서 시작합니다.
- 결론은 언제나 **"숫자 하나로 원인을 단정하지 않는다"** 쪽으로 모입니다.

### 7-4. 근거의 층위 구분 (가장 중요한 태도)
문장마다 다음 넷 중 무엇인지 분명히 밝힙니다.

| 층위 | 표현 예 |
|---|---|
| 공식 문서 | `[플랫폼] 도움말은 이렇게 설명합니다.` → 요지를 볼드로 |
| 현장 어림값 | `“~까지는 괜찮다”는 공식 기준이 아니라 현장에서 쓰는 어림값입니다.` |
| 팀의 비유·지론 | `저희 팀이 쓰는 비유입니다.` `제가 늘 강조하는 부분이기도 합니다.` |
| 가상 예시 | `설명을 위한 가상 예시이며 실제 성과가 아닙니다.` |

## 8. 마무리 패턴 ⭐ (세 글 동일)

```markdown
---
==[글 전체를 압축한 2줄 명제. 대조 또는 병렬 구문]==

대표님들, 오늘은(이번 주 회의 전에) [구체적 행동 하나] 해 보세요.
[행동 방법 1~2줄: ~하고, ~보시면 됩니다.]
**[이것만 해도 무엇이 바뀌는지 / ~라면 ~할 차례입니다.]**

참고: [공식 문서 링크]   ← 공식 기준을 인용한 경우만
```

- 2줄 요약은 **병렬 구조**를 좋아합니다: `A는 ~을, B는 ~을, C는 ~을 봅니다.`
- 행동은 **오늘이나 이번 주 안에**, 지금 쓰는 툴에서 바로 확인할 수 있는 작고 구체적인 것 하나입니다.
- 마지막 볼드 문장 템플릿:
  - `이 [두/세] 줄만 나란히 놓아도 ~가 보입니다.`
  - `~하는 것, 그게 ~의 첫걸음입니다.`
  - `둘이 이어지면 ~된 것이고, ~라면 ~부터 다시 ~할 차례입니다.`
- **수미상관**: 도입부의 문제 문장이나 현장의 말을 마무리에서 다시 불러와 닫습니다.

### 마무리 예시 (새로 쓴 예문)

```markdown
---
==재구매는 쿠폰이 아니라 첫 경험이 만듭니다.
그러니 할인율보다 첫 주문 뒤 일주일을 먼저 설계해야 합니다.==

대표님들, 오늘은 지난달 첫 구매 고객 명단을 열어
30일 안에 다시 산 사람이 몇 명인지만 세어 보세요.
그 옆에 그분들이 남긴 리뷰를 나란히 붙여 두시면 됩니다.
**이 두 줄만 나란히 놓아도
“쿠폰을 더 키우자”는 말 대신 무엇을 고칠지가 보입니다.**
```

### 사이트 고정 CTA (본문과 별개)
- 마무리 뒤 `---`, 그다음 H2 **"우리 브랜드도 이런 고민 중이라면,"**
- 막혀 있는 지점을 남겨 달라는 요청과, 광고 계정·상세페이지·리뷰를 같이 보고 어디부터 손댈지 말씀드리겠다는 2문장, 그리고 "마케팅 상담 신청" 버튼으로 구성됩니다.
- 사이트 템플릿이므로 **본문을 쓸 때 새로 만들지 않습니다.**

## 9. 자주 받는 질문(FAQ) 패턴

- **항상 3개**, H3 `Q. ~인가요? / ~나요? / ~아닌가요?`
- 질문은 독자가 실제로 품을 법한 의심·오해를 구어로 씁니다: `~하면 되는 거 아닌가요?`, `~도 조심해야 하나요?`
- 답변은 3~4줄이고, **첫 문장에서 바로 답합니다.** 다만 예/아니오로 잘라 말하지 않고 조건을 붙입니다:
  - `~일 수는 있습니다. 하지만 ~.`
  - `A의 문제가 아니라 B의 문제입니다.`
  - `그럴 수도 있고 아닐 수도 있습니다.`
  - `~면 충분합니다.`
- 마지막 줄은 실행 지시로 닫습니다: `~는 따로 보세요.` / `~는 모두 적어 두세요.`
- 필요하면 핵심 문장 하나만 볼드로 씁니다.

### FAQ 예시 (새로 쓴 예문)

```markdown
### Q. 리뷰 이벤트를 하면 재구매도 늘지 않나요?

첫 리뷰를 모으는 데는 도움이 될 수 있습니다.
하지만 리뷰를 남긴 사람과 다시 사는 사람은 같은 사람이 아닐 때가 많습니다.
**이벤트 참여율과 재구매율은 따로 보세요.**
```

## 10. 강조·서식 체계

| 장치 | 렌더링 | 빈도 | 쓰는 곳 | 규칙 |
|---|---|---|---|---|
| 형광펜 | 노란 배경(#F2FF00) + 볼드, `<mark>` | 글당 6개 | 도입부 1, 섹션 결론 4, 마무리 1 | 1~2줄짜리 명제. 대조 구문. **섹션당 최대 1개**. 단독 문단으로도 씀 |
| 볼드 | `**` | 글당 25~28개 | 문단 속 핵심 구, 문단 마지막 결론 줄, 도입부 셀프 체크, 가상 인물 이름 | 구·문장 단위로. 단어 하나만 볼드는 드묾 |
| 메모 박스 | 왼쪽 4px 검은 세로선 + 흰 배경 + 작은 라벨 | 글당 1~2개 | 가상 숫자, 예시 양식(요청서·가설 메모) | 라벨 예: `가정`, `~ 예시 (가상)`, `~ 메모 (가상)` |
| 인용 블록 | `>` | 글당 0~1개 | 독자의 반문 한 줄 | 바로 다음 문단에서 `여기서 많이들 오해하십니다.`로 받음 |
| 셀프 체크 | 볼드 문단 | 도입부 1회 | 잘못된 통념 3개 | `<ol>` 목록이 아니라 볼드 텍스트 `1.` `2.` `3.` |
| 불릿 목록 | `-` | 글당 0~1개 | 공식 기준 나열, 워크시트 항목 | 워크시트형은 `**라벨:** 내용` |
| HTML 표 | 표 | 필요할 때만 | 수정 전·후 비교, 구간별 대본 | 셀은 명사형 |
| 구분선 | `---` | 2회 | 마무리 앞, CTA 앞 | |
| 링크 | 본문 | 거의 없음 | 마지막 `참고:` 출처 1줄 | 공식 도움말만 |

### 문장부호

| 부호 | 쓰임 |
|---|---|
| 큰따옴표 “ ” | 사람이 하는 말, 회의 대사, 현장의 말, 버튼·자막 문구 |
| 작은따옴표 ‘ ’ | 개념어, 강조하고 싶은 단어, 화면 상태명, 메모에 적는 말(‘미확인’) |
| 가운뎃점 · | 명사 나열 (`계정·캠페인·광고`, `취소·반품`) |
| 화살표 → | 순서·흐름 (`결핍 → 감정 → 행동`), 숫자 변화 (`120만 원 → 180만 원`) |
| 물결 ~ | 범위 (`2~7일`, `0~5초`) |
| 콜론 : | 소제목의 앞뒤 연결, 메모 양식의 라벨 |

## 11. 글과 이미지 조합 패턴 ⭐

### 11-1. 기본 규칙
- **글당 정확히 3장.** 실사 사진, 스톡 이미지, 일러스트는 쓰지 않습니다. 전부 **요약 표 형태의 인포그래픽 카드**입니다.
- **위치**: 해당 섹션 본문이 끝난 뒤, 대개 그 섹션의 형광펜 결론 바로 다음, 다음 H2 바로 앞입니다. 섹션 시작에는 두지 않습니다.
- 도입부, FAQ, 마무리에는 이미지를 넣지 않습니다.
- **분포**: 글 앞 1/3 지점부터 끝 4/5 지점 사이에 고르게 놓습니다. 보통 비유 섹션, 구조 분해 섹션, 숫자 예시나 워크시트 섹션에 하나씩입니다.
- 이미지는 **새 정보를 주지 않습니다.** 방금 읽은 섹션을 표 한 장으로 다시 정리하는 '복습 카드'입니다.
- 글자 수로 보면 본문 약 2,000자마다 1장입니다.

### 11-2. 이미지 디자인 스펙 (모든 이미지가 같은 템플릿)
- **크기**: 가로형, 폭 1816px, 높이 830~1034px (약 2:1)
- **배경**: 흰색, 얇은 바깥 테두리
- **좌상단**: 굵은 검정 **제목**(짧은 명사구) + 그 아래 회색 **부제**(한 문장)
- **본문**: 표 3~4열 × 4~5행
  - 헤더 행: 검정 배경 + 흰 글씨, 위쪽 모서리 둥글게
  - 일반 행: 흰 배경, 얇은 회색 구분선
  - **핵심 행 1개만** 연한 살구색 배경 + 볼드. 그 행의 결론 칸은 **주황색 글씨**
- **표 아래**: 회색 작은 각주 1줄. 가정·한계를 밝힘 (`설명을 위한 가정입니다.` / `이해를 돕는 비유입니다. 실제 구조를 그대로 설명한 것은 아닙니다.`)
- **우하단**: 회색 영문 워드마크 `BE MY MARKETER`
- **폰트**: 한글 산세리프 (Noto Sans KR / Pretendard 계열)
- **셀 문장**: 명사형으로 짧게 (`검색해서 비교 중`, `+24만 원`, `옷감·크기 조건`)
- **색**: 검정·흰색·회색 기본에 **주황 한 가지만** 포인트로 사용

### 11-3. 이미지 텍스트 공식

| 요소 | 공식 | 새로 쓴 예 |
|---|---|---|
| 제목 | 섹션 내용을 6~14자 명사구로 | 재구매 점검 순서 |
| 부제 | 섹션 형광펜 문장을 줄이거나, 예시 조건을 한 줄로 | 가상 예시: 첫 구매 200명, 30일 재구매 18명 |
| 표 열 | `[구분] / [상황·예시] / [확인할 것·결론]` 구조 | 단계 / 확인할 숫자 / 다음 행동 |
| 핵심 행 | 글이 가장 강조하는 경우 1개 | 첫 주문 후 7일 / 재방문율 / 배송 후 안내 점검 |
| 각주 | 가정·한계 고지 | 숫자는 설명을 위한 가정입니다. |

### 11-4. alt 텍스트와 캡션
- **alt**: `[이미지 제목] - [이미지 부제]` 형식 그대로 씁니다.
- **캡션(figcaption)**: 합니다체 한 문장입니다. 섹션의 핵심 메시지를 다른 말로 다시 말합니다(형광펜 문장을 살짝 바꾼 경우가 많음).
  - `위 표는 ~를 보여 줍니다` 같은 이미지 설명은 쓰지 않습니다.
  - 템플릿: `[핵심 대조]입니다.` / `[행동 원칙]합니다.` / `~지만, ~입니다.`
  - 새로 쓴 예: `할인율을 바꾸기 전에 첫 주문 뒤 일주일부터 확인합니다.`

## 12. 그 외 눈에 띄는 특징

1. **근거의 층위를 철저히 나눕니다.** 공식 문서 / 현장 어림값 / 팀의 비유 / 가상 예시를 문장마다 구분해서 말합니다. (7-4 참고)
2. **통념을 바로잡되 공격하지 않습니다.** "틀렸다" 대신 `아직은 이릅니다`, `근거는 없습니다`, `~로 볼 필요는 없습니다`를 씁니다.
3. **성급하게 결론 내지 않는 태도 자체가 메시지입니다.** `숫자 하나로 원인을 단정하지 않습니다`, `한 번에 뛰어가지 마세요`, `모르는 칸은 ‘미확인’이라고 씁니다`.
4. **실행 순서를 늘 제시합니다.** 먼저 → 그다음 → 그래도 안 되면. `바로 고칠 문제 / 기다릴 문제 / 그때 바꿀 문제` 같은 3단 분류를 좋아합니다.
5. **기록 습관을 강조합니다.** `날짜와 이유를 한 줄로 남깁니다`, `한 장에 적는 워크시트`, `집행 전에 미리 정해 둡니다`.
6. **윤리적인 선을 긋습니다.** 과장과 불안 조장을 경계합니다. `없던 불안을 만들어 내는 기술이 아닙니다`, `알려야 할 정보를 줄이는 핑계가 아닙니다` 같은 문장이 들어갑니다.
7. **자기 노출이 절제되어 있습니다.** 성과 자랑, 고객사 실명, 매출 과시가 없습니다. 경험은 `저희는 ~하는 편입니다` 정도로만 드러냅니다.
8. **수미상관으로 닫습니다.** 도입부에서 던진 현장의 말을 마무리에서 다시 불러와 "확인할 수 있는 질문"으로 바꿔 줍니다.
9. **블로그 상투구가 없습니다.** `안녕하세요`, 자기소개, `오늘 포스팅에서는`, `~에 대해 알아보겠습니다`, `도움이 되셨길 바랍니다` 같은 말을 쓰지 않고, 첫 줄부터 장면으로 들어갑니다.
10. **추상 → 일상 비유 → 실무 순으로 내려옵니다.** 어려운 개념을 바로 실무로 설명하지 않고, 누구나 떠올릴 수 있는 장면을 한 번 거칩니다.
11. **실무 디테일이 구체적입니다.** 어느 화면의 어느 날짜를 보라는 식으로, 독자가 지금 바로 열어 볼 수 있는 수준까지 내려갑니다.

## 13. 금지 목록 (Don't)

- ❌ `안녕하세요, ○○입니다`, `오늘은 ~에 대해 알아볼게요`, `도움이 되셨나요?`, `구독·좋아요`
- ❌ 느낌표, 이모지, 💡✅ 같은 아이콘, 해시태그
- ❌ `무조건`, `반드시 성공`, `100%`, `꿀팁`, `치트키`, `대박`, `핵심 꿀팁 3가지!`
- ❌ 해요체 평서문 (`~해요.` `~거든요.`)
- ❌ `여러분`, `고객님` 호칭
- ❌ 줄바꿈 없이 4문장 이상 이어 쓴 문단
- ❌ 한 섹션에 형광펜 2개 이상, 단어 하나에만 형광펜
- ❌ 실사 사진·스톡 이미지·장식용 이미지
- ❌ `▲ 위 이미지는 ~` 같은 이미지 설명 캡션
- ❌ 가상 숫자를 실제 성과처럼 쓰기, 출처 없는 통계
- ❌ 본문을 불릿 목록으로 대체하기 (본문은 줄글이 기본)
- ❌ 독자를 겁주거나 불안을 키우는 표현

## 14. 작성 후 셀프 점검표

- [ ] 제목이 `[개념]이란? [부제]` 형식인가
- [ ] "이 글의 순서"에 H2 8~9개가 그대로 들어갔나
- [ ] 첫 H2가 정의형인가
- [ ] 도입부 4단계(장면 → 반응 → 볼드 체크 3개 → 형광펜 + 예고)를 지켰나
- [ ] 평서문이 모두 합니다체인가, 느낌표가 0개인가
- [ ] 한 줄에 한 문장씩, 문단 3~6줄로 끊었나
- [ ] "A가 아니라 B" 구문이 여러 번 들어갔나
- [ ] "그래서 저희는 ~" 문장이 2개 이상인가
- [ ] 형광펜이 6개 안팎(도입 1, 섹션 4, 마무리 1)인가
- [ ] 볼드가 25개 안팎인가
- [ ] 가상 예시와 비유의 한계를 밝혔나
- [ ] 공식 기준과 현장 어림값을 구분했나
- [ ] 이미지 3장이 섹션 끝에 있고, 표 형식·alt·캡션 규칙을 지켰나
- [ ] FAQ가 `Q.` 3개이고, 첫 문장에서 바로 답하나
- [ ] 마무리가 형광펜 2줄 + "대표님들, 오늘은 ~해 보세요." + 볼드 마지막 줄인가
- [ ] 도입부의 문제 문장을 마무리에서 다시 불러왔나
- [ ] 본문이 공백 포함 6,000~6,500자 안팎인가
