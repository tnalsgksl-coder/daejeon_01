# 일본어 교육 영상 AI 에이전트 설계서

Oct 27, 2026 · @수민

## 개요

총괄 매니저 AI에게 지시하면 13개 역할 AI가 기획부터 업로드까지 이어서 처리하고, 결과를 다시 사용자에게 보고하는 일본어 교육 영상 제작 시스템이다. 사용자는 최고 관리자 자리에서 지시하고, 세 번만 승인한다. 팀은 기획, 콘텐츠, 제작, 출시 4개이며, 일본어 감수는 대본과 자막 단계에서 두 번 거친다.

## 전체 구조

총괄 매니저는 직접 만들지 않고 지시 해석, 작업 배분, 진행 관리, 사용자 보고만 맡는다. 13개 역할의 입력과 출력은 다음과 같다.

| 팀 | 역할 | 입력 | 출력 |
| --- | --- | --- | --- |
| 총괄 | 총괄 매니저 | 사용자 지시 | 작업 티켓, 진행 보고서 |
| 기획 | 주제 선정 | 지시, 과거 영상 목록, 트렌드 | 주제 후보 3\~5개 (근거 포함) |
| 기획 | 커리큘럼 설계 | 승인된 주제 | 레벨, 학습 목표, 핵심 표현 목록 |
| 콘텐츠 | 대본 작가 | 학습 목표, 표현 목록 | 장면별 일본어 대본 |
| 콘텐츠 | 일본어 감수 | 대본 또는 자막 | 통과 또는 반려 (사유와 수정 위치) |
| 콘텐츠 | 한국어 해설·번역 | 감수 통과된 대본 | 번역, 해설, 자주 하는 실수 |
| 제작 | 나레이션 디렉터 | 확정 대본 | 음성 파일, 장면별 길이표 |
| 제작 | 비주얼 디자이너 | 대본, 길이표 | 슬라이드와 이미지 소재 |
| 제작 | 영상 편집 | 음성, 비주얼, 음원 | 자막 없는 영상 초안 |
| 제작 | 자막 담당 | 대본, 음성 타임코드 | 자막 파일 (일본어, 후리가나, 한국어) |
| 제작 | 에셋·파일 정리 | 모든 산출물 | 규칙에 맞는 폴더, 버전 기록 |
| 출시 | 품질·저작권 검수 | 완성본, 자막, 소재 출처 | 체크리스트 결과, 통과 또는 반려 |
| 출시 | 제목·썸네일·업로드 | 승인된 최종본 | 제목, 설명, 태그, 썸네일, 업로드 패키지 |
| 출시 | 성과 분석 | 조회수, 이탈 구간 데이터 | 개선 제안, 기획팀 전달 |

## 작업 흐름과 승인 지점

사용자가 결정하는 곳은 세 곳이고, 나머지는 AI 팀이 티켓으로 넘겨받는다. 업로드는 최종 승인 없이는 진행하지 않는다.

1. 승인 1 (기획 직후): 주제와 학습 목표를 확정한다.
2. 승인 2 (대본 확정): 일본어 감수를 통과한 대본을 제작 전에 확정한다. 음성, 이미지, 렌더링은 비용이 크기 때문이다.
3. 승인 3 (최종본): 품질·저작권 검수를 통과한 영상을 업로드 전에 확정한다.

감수에서 반려되면 대본 작가나 자막 담당이 고쳐 다시 감수를 받고, 세 번의 승인을 모두 지나야 업로드와 성과 분석으로 넘어간다.

## 감수와 반려 규칙

일본어 감수는 대본 단계와 자막 단계에서 두 번 하고, 반려는 사유와 수정 위치를 함께 보낸다. 같은 작업이 2회 연속 반려되면 사용자에게 보고한다.

- 1차 감수(대본): 문법, 어휘, 자연스러움, 목표 레벨(JLPT)에 맞는 난이도를 본다.
- 2차 감수(자막): 후리가나, 한자 읽기, 자막과 음성의 일치 여부를 중점적으로 본다.
- 반려 형식: 사유와 수정 위치를 반드시 함께 적는다.
- 반려 상한: 같은 작업이 2회 연속 반려되면 총괄 매니저가 사용자에게 에스컬레이션한다. 무한 반복을 막기 위해서다.
- 품질 검수 반송: 싱크 문제는 자막, 발음 문제는 나레이션, 음원 문제는 영상 편집, 오탈자는 자막 또는 대본 담당에게 보낸다.

## 작업 티켓 양식

모든 역할은 같은 양식의 티켓으로 일을 주고받아서 결과가 흐트러지지 않는다. 감수나 검수가 끝나면 상태를 통과 또는 반려로 바꾸고, 반려일 때만 feedback에 사유와 위치를 적는다.

```json
{
  "ticket_id": "JP-2026-014",
  "from": "대본 작가",
  "to": "일본어 감수",
  "status": "검수 요청",
  "attempt": 1,
  "input_files": ["scripts/JP-014_v1.md"],
  "request": "N4 수준 문법 오류와 부자연스러운 표현 검수",
  "feedback": null
}
```

상태값은 작업 요청, 검수 요청, 통과, 반려, 승인 대기, 승인됨, 에스컬레이션 일곱 가지로 둔다.

## 외부 도구 연결

텍스트 역할은 언어 모델만으로 충분하지만, 음성, 이미지, 영상 렌더링, 업로드는 별도 도구와 연결해야 한다. 아래는 후보이며, 버전과 약관은 도입 전에 공식 문서에서 확인한다.

| 역할 | 도구 후보 | 비고 |
| --- | --- | --- |
| 주제 선정 | YouTube Data API, Google Trends, 웹 검색 | 경쟁 영상 조사 포함 |
| 일본어 감수 | MeCab, Sudachi, JMdict, JLPT 단어 목록 | AI 판단에 더해 읽기와 난이도를 기계적으로 교차 검증 |
| 나레이션 | VOICEVOX(무료, 로컬), Google Cloud TTS, Azure TTS, ElevenLabs | 음성별 상업 이용과 크레딧 표기 조건 확인 필수 |
| 비주얼 | 이미지 생성 API, 로컬 Stable Diffusion, python-pptx, Playwright | 슬라이드는 HTML로 만들어 이미지로 캡처하는 방식이 편함 |
| 영상 편집 | FFmpeg, MoviePy, Remotion, Shotstack, Creatomate | 직접 렌더링은 FFmpeg나 MoviePy가 무난 |
| 자막 | SRT·ASS 파일, Whisper, pykakasi, fugashi | 후리가나는 SRT로 표현이 어려워 ASS 형식 또는 화면 합성 |
| 에셋·파일 정리 | 로컬 폴더 + Git, Google Drive, S3, SQLite, Notion, Airtable | 티켓 상태 기록용 DB 겸용 |
| 품질·저작권 검수 | 무료 음원·이미지 라이선스 목록, 출처 기록표 | 소재마다 출처와 라이선스 기록 |
| 업로드 | YouTube Data API | 공개 업로드는 API 프로젝트 심사가 필요할 수 있음 |
| 성과 분석 | YouTube Analytics API | 이탈 구간을 다음 대본 개선에 활용 |
| 승인 요청 | Slack, Discord, Telegram 봇 | 버튼 한 번으로 승인과 반려 처리 |

연결 방식은 세 가지다.

- 노코드 자동화(n8n, Make 등): 박스를 선으로 이어 흐름을 만든다. 입문에 좋지만 복잡한 반려 루프는 번거롭다.
- 코드로 직접 구현(Python + Claude API): 역할마다 지시문과 도구 함수(TTS 호출, FFmpeg 실행 등)를 정의하고 AI가 필요할 때 호출하게 한다. 가장 유연하다. LangGraph, CrewAI 같은 멀티 에이전트 프레임워크를 쓰면 역할 분담과 반려 루프를 더 쉽게 짤 수 있다.
- MCP로 도구 표준화: 도구를 MCP 서버로 만들면 여러 역할이 같은 방식으로 호출하고, 나중에 도구를 바꾸기 쉽다. 도구가 많아졌을 때 유리하다.

## 진행 로드맵

처음부터 모든 역할을 자동화하지 않고 세 단계로 나눠서 키운다. 처음에는 역할을 4\~5개로 합쳐 작게 시작해도 된다.

1. 수동 단계: 대화로 각 역할 프롬프트를 시험하며 티켓 양식과 산출물 형식을 확정한다.
2. 반자동 단계: 텍스트 역할(기획, 대본, 감수, 번역, 자막)만 n8n이나 Python 스크립트로 연결한다. 함께 제공하는 예제 코드가 이 단계에 해당한다.
3. 풀 자동 단계: TTS, 이미지 생성, FFmpeg 렌더링, 업로드를 붙이고 승인 봇을 단다.

## 주의 사항

- 저작권: 음원, 이미지, 음성(TTS) 모두 상업 이용 조건과 출처 표기를 확인한다. 품질·저작권 검수 역할이 소재별 출처를 기록한다.
- 비용: 역할이 많을수록 AI 호출이 늘어난다. 무료 플랜은 한도에 빨리 닿을 수 있어 자동화에는 API 이용을 고려한다. API는 claude.ai 구독과 별도로 과금되며, 가격은 공식 문서에서 확인한다.
- 품질: 교육 영상은 틀린 내용이 치명적이므로 일본어 감수는 AI 판단과 사전·형태소 분석 도구 검증을 함께 쓴다.
- 보안: API 키와 업로드 계정 정보는 코드에 직접 쓰지 않고 환경 변수로 관리한다.
- 승인: 업로드와 외부 공개 단계는 사용자 승인 없이 자동으로 진행하지 않는다.
